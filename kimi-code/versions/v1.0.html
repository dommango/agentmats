Keyboard & TUI

General input
ItemDescription
#EnterSubmit the current input
#Shift-Enter / Ctrl-JInsert a newline in the input
#Up / DownBrowse input history
#EscClose a popup, cancel completion, or interrupt streaming and compaction
#Ctrl-CInterrupt streaming output, or clear the input box
  • During streaming it cancels immediately, with no second confirmation.
  • With an empty input box it exits, but only on a second press — any other key clears the confirmation.
#Ctrl-DExit when the input box is empty
  • Double-press confirmation, like Ctrl-C on an empty box.
#Ctrl-TExpand or collapse the todo list when it is truncated
#Ctrl-P / Ctrl-NPage through the experimental Updates panel

Mode switching
ItemDescription
#Shift-TabToggle Plan mode
  • In Plan mode the agent prefers read-only tools and may write the plan file.
  • Bash still follows the current permission mode — Plan mode adds no separate approval.
  • Toggling alone does not create an empty plan file.
#!Enter shell mode from an empty input box
  • While a command runs, Ctrl-B moves it to a background task.

Input & editing
ItemDescription
#Ctrl-GEdit the current input in an external editor
  • Editor priority: the /editor setting, then $VISUAL, then $EDITOR.
  • Saving replaces the input box; exiting without saving leaves it unchanged.
#Ctrl-VPaste an image or video from the clipboard (Unix, macOS)
  • On Windows use Alt-V.
  • A placeholder appears in the box; the media is sent when you submit.
#Ctrl--Undo
#Esc EscOpen the undo selector (double-press while idle)

During streaming
ItemDescription
#Ctrl-SSteer: inject the current input into the running turn
  • The model sees your message at the next interruptible point, without waiting for the turn to finish.
  • Also promotes a queued external skill command into the running turn.

Tool output
ItemDescription
#Ctrl-OExpand or collapse tool output, shell output and compaction summaries
  • Since 0.42.0 finished tool calls collapse to a header plus one outcome row; hidden output is counted and revealed here.

Approval panel
ItemDescription
#1 / 9Select the option at that index directly
#Ctrl-EExpand or collapse a diff or file preview in the panel
#Esc / Ctrl-C / Ctrl-DReject the current request
  • Options needing feedback switch to an input state: type, then Enter to submit or Esc to go back.

Session management
ItemDescription
#/new / /clearStart a fresh session, discarding the current context
#/sessions / /resumeBrowse and switch to a historical session
#/forkFork a new session from this one, keeping full history
  • You stay in the current session.
#/title / /renameShow or set the session title (max 200 characters)
#/compactCompact the conversation context to free tokens
  • An optional instruction hints to the model what to preserve.
#/undoUndo recent prompts from the active context
  • Without a count it opens a selector; prompts before the last compaction cannot be undone.
  • Also rolls back the todo list and plan-mode state — code changes are not reverted.
#/reload / /reload-tuiReload the session and apply the latest config.toml and tui.toml
  • /reload-tui reloads only the UI preferences, without rebuilding the session.
#/tasks / /taskBrowse the background task list
#/add-dirAdd an extra workspace directory to this session
  • Run it with no path, or with list, to list configured directories.
  • You can choose to remember the directory for the project in .kimi-code/local.toml.
#/exit / /quit / /qExit the CLI

Modes & run control
ItemDescription
#/yolo / /yesPreselect Ask When Needed in the permission list
  • Routine edits and commands run automatically; risky actions, questions and plans still ask.
  • Plan-mode exit approval is not bypassed, and Bash in Plan mode still follows the allow rules.
#/autoPreselect Never Ask in the permission list
  • Kimi never interrupts you; everything runs and is decided automatically.
#/planToggle Plan mode, or force it with on / off
  • /plan clear clears the current plan.

Export & sharing

#/export-debug-zipExport the session as a debug ZIP archive
#/copyCopy the last assistant message to the clipboard
#/webOpen the current session in the web UI
  • Connect to a running server, or start a new foreground server after the TUI exits.

Information & status

  • In the panel: ↑/↓ scroll a line, PageUp/PageDown scroll 10, and Esc, Enter, q or Q closes it.

#/usageShow token usage, context consumption and quota

Slash Commands (Tools)

Swarm & goals
ItemDescription
#/swarm on / /swarm offTurn swarm mode on or off without sending a prompt
#/swarm <task>Turn swarm mode on and send the task as a prompt
  • Swarm mode turns off automatically when the turn completes normally.
  • In manual permission mode Kimi asks whether to switch to Ask When Needed or Never Ask first.
#/goalStart or manage an autonomous goal
  • A persistent objective Kimi works toward across automatically continuing turns.
  • /goal or /goal status shows status, elapsed time, turn count and token count.
#/goal pause / /goal resume / /goal cancel / /goal replacePause, resume, cancel or replace the saved goal
#/goal nextQueue an upcoming goal for this session
  • The agent does not see queued goals until the current goal completes.
  • /goal next manage opens the reorder manager (Space selects, ↑/↓ move, E edits, D deletes).
  • Put -- after /goal when the objective itself starts with a subcommand word.

CLI & Subcommands

Flags
ItemDescription
#-V, --version / -h, --helpPrint the version number
#-S, --session [id]Resume a session; with no id, pick interactively

  • Defaults to default_model in config.toml.

  • In goal mode it exits 0 when the goal completes, 3 when it blocks and 6 when it pauses.

  • Cannot be combined with --session or --continue.

  • Treated as explicit launch intent: it may override a same-name built-in agent and outranks every directory scope.
#--add-dir <dir>Add an extra workspace directory for this session; repeatable

Settings (config.toml)

Files
ItemDescription
#~/.kimi-code/config.tomlMain config, created on first run
  • Relocate the whole data root with KIMI_CODE_HOME; the file name is always config.toml.
  • Field names are snake_case; a key containing a dot must be quoted, e.g. [models."gpt-4.1"].
#~/.kimi-code/tui.tomlTerminal-UI and client preferences, alongside config.toml
  • /config, /theme and /editor write it for you.
  • A malformed file falls back to defaults with a notice rather than failing to start.
#.kimi-code/local.tomlProject-local settings that should not be shared
  • Written when /add-dir remembers a directory for the project.
  • Holds absolute paths, so add it to .gitignore.
#$KIMI_CODE_HOME/SYSTEM.mdPermanently replaces the main agent’s system prompt
  • Only the prompt — description, tool set and delegation allowlist stay from the built-in defaults.
  • Applies in every launch mode; a project agent file with override: true and --agent-file both rank ahead of it.
#kimi doctorValidate the configuration files

Top-level
ItemDescription
#default_modelDefault model alias; must be defined in models
#default_permission_modePermission mode for new sessions: manual, yolo or auto
#default_plan_modeWhether new sessions start in Plan mode
#merge_all_available_skillsMerge skills from all available directories
#extra_skill_dirs / extra_agent_dirsExtra skill search directories layered on the defaults
#builtin_product_skillsOffer the built-in skills documenting Kimi Code to the model
#telemetryAnonymous telemetry; disabled only when explicitly set to false

Models & providers
ItemDescription
#[providers."<id>"]API provider entry: type, base_url, api_key
#[models."<alias>"]Model alias entry
  • Fields include provider, model, max_context_size, capabilities, display_name, support_efforts, default_effort.
#[secondary_model]Subagent model pool
  • Always on as of 0.42.0 — the experimental flag and its opt-out env var were removed.
  • Pool entries can each carry a different thinking effort.
#[thinking]Thinking-mode defaults: enabled, effort, keep
#[token_counting]How context tokens are reported externally

Runtime
ItemDescription
#[loop_control]Agent loop limits
  • Includes max_attempts_per_step, max_steps_per_turn and reserved_context_size.
#[background]Background task runtime
  • max_running_tasks caps concurrency; keep_alive_on_exit decides whether tasks survive session close.
#[subagent] / [swarm]Subagent and AgentSwarm limits such as timeout_ms
#[tools]Global tool switch
#[read]Character limits and resumable long-line file reads
  • Added in 0.42.0 so long lines no longer produce repeated output truncation.
#[image]Image compression parameters such as max_edge_px
#[database]Session-index read model and global search worker
  • Replaced the experimental minidb flags in 0.42.0; both default to on.
#[services]Built-in external services
  • [services.moonshot_search] and [services.moonshot_fetch] each take a base_url and api_key.
#[identity]Custom agent identity — the name it calls itself and its client slug

Permissions & hooks
ItemDescription
#[[permission.rules]]Initial permission rules, each a decision plus a pattern
  • Example: decision = "deny" with pattern = "Bash(rm -rf*)".
#[[hooks]]Lifecycle hooks, declared as an array of tables

Environment Variables

Core paths
ItemDescription
#KIMI_CODE_HOMEData root; defaults to ~/.kimi-code
  • Config, sessions, logs, OAuth credentials, Kimi-specific skills and the global AGENTS.md all move with it.
  • Generic ~/.agents/ resources stay under the real OS home so they can be shared across tools.
  • Instances sharing one root share config and credential files.
#KIMI_DISABLE_TELEMETRYTurn off anonymous telemetry reporting
#KIMI_CODE_CUSTOM_HEADERSAttach newline-separated Name: Value headers to every model request
  • Kimi identity headers and a provider’s custom_headers override same-named entries here.
  • Never use it for authentication or reserved headers — a case variant merges with the real header and can break requests.
#KIMI_CODE_PASSWORDParallel auth credential for kimi web
  • Recommended when binding beyond loopback; when unset, only the token is valid.

Models
ItemDescription
#KIMI_MODEL_NAMESynthesise a temporary in-memory provider and model, without touching config.toml
  • The change does not persist after restart.
#KIMI_MODEL_THINKING_EFFORTForce a thinking effort, bypassing the model’s declared support_efforts
  • kimi provider only.
#KIMI_MODEL_TEMPERATURE / KIMI_MODEL_TOP_P / KIMI_MODEL_MAX_COMPLETION_TOKENSSampling controls applied to every request
  • Global and kimi-provider only, independent of KIMI_MODEL_NAME.
  • KIMI_MODEL_MAX_COMPLETION_TOKENS hard-caps completion tokens per step; 0 disables clamping.

Runtime switches
ItemDescription
#KIMI_CODE_BACKGROUND_KEEP_ALIVE_ON_EXITKeep background tasks when the session closes
#KIMI_CODE_BACKGROUND_MAX_RUNNING_TASKSCap concurrently running background tasks
#KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCYCap AgentSwarm subagents during the initial ramp
#KIMI_SUBAGENT_TIMEOUT_MS / KIMI_CODE_SWARM_TIMEOUT_MSWall-clock ceiling for one Agent subagent
#KIMI_LOOP_MAX_STEPS_PER_TURN / KIMI_LOOP_MAX_ATTEMPTS_PER_STEPMax agent steps per turn; 0 is unlimited
#KIMI_MCP_STARTUP_TIMEOUT_MS / KIMI_MCP_TOOL_TIMEOUT_MSDefault MCP connection timeout
  • Overrides the config file, but mcp.json startupTimeoutMs / toolTimeoutMs still win.
#KIMI_CODE_PLUGIN_MARKETPLACE_URLOverride the marketplace JSON loaded by /plugins
  • Also accepts http://, file:// and local paths.
#KIMI_CODE_NO_AUTO_UPDATEDisable the update preflight entirely
  • The legacy alias KIMI_CLI_NO_AUTO_UPDATE is still honoured.
#KIMI_DISABLE_CRONDisable the scheduled-task tool
  • CronCreate rejects new schedules and existing tasks stop firing.
#KIMI_CODE_INFINITE_RETRYRetry failed LLM requests indefinitely
  • Exponential backoff capped at 32 s, honouring Retry-After; aborting still cancels immediately.

Experimental (churns between releases)
ItemDescription
#KIMI_CODE_EXPERIMENTAL_FLAGEnable every registered experimental feature for this process
  • Experimental flags are short-lived: 0.42.0 removed KIMI_CODE_EXPERIMENTAL_REMOTE_CONTROL and KIMI_CODE_EXPERIMENTAL_SECONDARY_MODEL once those features became always-on.
#KIMI_CODE_EXPERIMENTAL_SUBAGENT_FORKStart a subagent from a snapshot of the caller’s history
#KIMI_CODE_TUI_FULL_SCREENExperimental fullscreen UI
  • Scrollable transcript, mouse selection, clickable links and Ctrl-Shift-F search.
#KIMI_CODE_SEARCH_WORKER / KIMI_CODE_PERSISTENCE_MINIDB_READMODELRun the global search index in a dedicated worker thread
  • Replaced the experimental minidb flags in 0.42.0; both default to on and map to [database].

Diagnostics
ItemDescription
#KIMI_LOG_LEVELLog level: off, error, warn, info, debug
  • Read once at process startup, like every other log variable.
  • Rotation is controlled by KIMI_LOG_GLOBAL_MAX_BYTES, KIMI_LOG_GLOBAL_FILES, KIMI_LOG_SESSION_MAX_BYTES and KIMI_LOG_SESSION_FILES.

Skills, Agents & AGENTS.md

Skills
ItemDescription
#SKILL.mdThe main file of a directory-form skill
  • Directory form is recommended: <name>/SKILL.md plus scripts and reference material alongside it.
  • When both <name>/SKILL.md and a same-named <name>.md exist, the subdirectory wins.
  • Frontmatter name and description are both required in directory form — omitting either fails to parse.
#$KIMI_CODE_HOME/skills/Kimi-specific user skills; moves with the data root
#~/.agents/skills/Generic user skills, shared across tools
  • Stays under the real OS home even when KIMI_CODE_HOME is relocated.
#.kimi-code/skills/ / .agents/skills/Project skills
#--skills-dirLoad skills from an explicit directory instead of auto-discovery
#extra_skill_dirsExtra skill search directories layered on the defaults
  • merge_all_available_skills controls whether all discovered directories are merged.

Agents
ItemDescription
#$KIMI_CODE_HOME/agents/ / ~/.agents/agents/Kimi-specific user agents
#.kimi-code/agents/ / .agents/agents/Project agents
#override: trueLets an agent file replace a same-name built-in agent
  • Security-relevant: a project file named agent.md with this flag replaces the default main agent’s entire system prompt, and coder.md replaces the default sub-agent type.
  • Unlike AGENTS.md, which is injected as reference data, an override file is the system prompt — and a file with no tools list keeps every tool.
  • Treat .kimi-code/agents/ in an unfamiliar repository with the same caution as a script.
#${base_prompt}Embeds the effective default system prompt inside an agent file
  • Lets a file wrap the default behaviour instead of replacing it.
  • ${plugin_sections} places plugin-contributed instructions; ${agents_md} inserts the workspace instruction files.
#--agent / --agent-fileSelect an agent profile for a new session

Hooks & MCP

Hook configuration
ItemDescription
#[[hooks]]One hook entry in config.toml
  • event and command are required; matcher is an optional regex over the event target; timeout is 1-600 seconds, default 30.
#matcherRegex filtering which event targets fire the hook
  • Omitted means every target matches.
#exit 0 / exit 2Hook exit codes: 0 allows, 2 blocks
  • On 0 execution continues and stdout may be appended to context.
  • On 2 the operation stops and stderr is used as the reason.

Hook events
ItemDescription
#UserPromptSubmit / UserPromptQueuedFires when you send a message; can block the model call this turn
#PreToolUseFires before a tool call, ahead of permission checks; blocking stops the tool
#PostToolUse / PostToolUseFailureFires after a tool succeeds
#PermissionRequest / PermissionResultFires just before waiting for approval
#SessionStart / SessionEndFires after a session starts or resumes
  • The payload carries source, model and profile; SessionEnd distinguishes exit from archive.
#SessionHeartbeatFires every 60 seconds while the session is alive
  • The timer only runs when this event is configured.
#TurnStartedFires when a new turn begins, with its origin kind
#Stop / StopFailureFires when the model is about to end the turn; blocking lets it continue
#InterruptFires when you interrupt the turn, in place of Stop
  • Not fired for timeouts or programmatic aborts.
#SubagentStart / SubagentStopFires around sub-agent runs
#TaskStartedFires when a background task starts
#PreCompactFires before context compaction; return values are ignored entirely

MCP
ItemDescription
#mcp.jsonMCP server configuration, at user and project level
  • User level $KIMI_CODE_HOME/mcp.json; project level .kimi-code/mcp.json, which wins on a name clash.
  • Transports: stdio (command + args), HTTP (url), and legacy transport: "sse".
#mcp__<server>__<tool>How MCP tools are named for permission rules
  • Rules support * and ** wildcards; tool parameters are not part of the match.
  • Unmatched calls raise an approval request; "Approve for this session" allows the same kind for the rest of the session.
  • In Ask When Needed mode MCP calls are auto-approved — only use it when you trust every connected server.
#[mcp] startup_timeout_ms / [mcp] tool_timeout_msGlobal MCP connection timeout, default 30000 ms
  • A per-server startupTimeoutMs / toolTimeoutMs in mcp.json wins over both the config and the env vars.
#kimi acpRun Kimi Code as an Agent Client Protocol server over stdio
#kimi webRun the local server and web UI
  • kimi server is deprecated in its favour.
